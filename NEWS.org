*[Released]*

** v0.14.0 (2026-11-13)

*** Added

- *A launcher that looks like the shell's front door.* The card gained a brand
  header with a close button, a search entry with its own search icon, a
  rounded list trough, icon tiles (with a fallback for entries without an
  icon), a selected-row accent, a hover state and an empty-state message.  The
  material keeps the bar's palette but gets a launcher-sized corner radius,
  a soft highlight and a shadow.
- *Arrow keys scroll the launcher list with the selection.* Moving past the
  bottom row now moves the scroller to reveal it, and moving above the top row
  does the same; the selection and the viewport can no longer disagree.
- *Two more ways out of the launcher.* A close button in the header and a click
  anywhere on the dimmed area outside the card dismiss it, alongside Esc and
  choosing an entry.

*** Changed

- The launcher is a search surface now, not a plain entry: the entry is a
  =GtkSearchEntry= and the card separates header, query, results and key hints
  into their own visual bands.

*** Verified

- =tests/test_launcher.c= covers the scroll-follows-selection geometry and the
  outside-card click predicate.
- The full =meson test -C build --print-errorlogs= suite is green, and the
  release is checked in the pinned Guix environment before tagging.

** v0.13.0 (2026-11-13)

*** Added

- *A GUI settings window, reached by right-clicking the bar.* =Edit settings…=
  opens a normal GTK window with a page for the bar's placement and type, the
  theme, notifications, Wi-Fi, the global menu, and the tray and clock.  The
  controls are live: a change is saved and the bar reloads without closing the
  window.  =Reload settings= sits beside it in the bar's context menu.
- *GUI choices override the configuration without rewriting it.* The window
  writes an alist of =setting . value= pairs to
  =$XDG_STATE_HOME/whelk/preferences-<settings-stem>.scm= (or
  =~/.local/state/whelk/=).  The loader layers that file over =settings.scm=
  every time it reads the configuration, so a GUI choice wins, survives a
  restart and a hot reload, and remains reversible.  *Reset GUI settings*
  deletes the override and restores the file's values exactly.
- *A bar theme is now part of the bar description.* =bar-config-theme= and
  =WhelkBarConfig.theme= carry the theme name, which is what lets the settings
  window show and change the current theme; changing it also applies the new
  palette.

*** Changed

- The bar's right-click menu is new; right-clicking a module still keeps that
  module's own action, and right-clicking the bar around it opens the shell's
  menu.
- The settings window is styled as a task window rather than a bar surface:
  cards, a labelled page switcher, an override badge, and a footer that keeps
  Reset and Close where the eye expects them.

*** Fixed

- The loader now forgets a settings file's old registration before evaluating
  it, and binds the freshly loaded default configuration under the file's path.
  Without that, a GUI override registered on an earlier reload could survive a
  reset as a stale path registration.

*** Verified

- =tests/test_prefs.scm= covers the override path, save/read precedence, every
  GUI option's effect on the loaded bar, persistence across reload, and reset.
- =tests/test_preferences.c= covers the typed bridge and the actual widgets;
  the widget half skips on a headless runner.
- =meson test -C build --print-errorlogs= is green, and the release is built
  from the pinned Guix environment before tagging.

** v0.12.0 (2026-11-13)

*** Added

- *A configurable layer, for the niri overview.* =#:layer= accepts ='top=
  (default), ='bottom=, ='background= and ='overlay=.  Niri moves and zooms
  bottom/background layer surfaces with the workspace in its overview and keeps
  top/overlay fixed, which is why whelk's top-layer bar stayed put while a
  Waybar configured with ~"layer": "bottom"~ moved with the zoom.  Set
  ~#:layer 'bottom~ for that behaviour.  The layer is copied on reload, and the
  README explains the popover trade-off of a bottom bar.
- *A supervisor for the UI process.* The =whelk= you start is now a small
  parent whose child is the GTK/Guile shell.  A child crash is logged and the
  UI is restarted, with a bounded consecutive-failure count; a long-running
  shell that crashes starts a fresh count.  =WHELK_NO_SUPERVISE=1= runs the UI
  directly under a debugger or a test harness.
- *A clean shutdown path.* SIGTERM, SIGINT, SIGHUP and =--quit= leave the
  GApplication through the same shutdown as the menu: the clipboard history is
  flushed, =wl-paste= is stopped, the notification bus name is released, the
  settings monitor and REPL socket are removed, and every surface is destroyed.
  The supervisor forwards termination signals to the UI child and waits for it,
  so killing the main whelk process does not leave the shell behind.  It does
  not signal the child's whole process group, so an application launched from a
  bar action stays open.  Linux's parent-death signal covers a SIGKILL of the
  supervisor.
- *Expanded File, Edit and View menus.* File now carries the compositor's
  =Close Window= (Window keeps the arranging verbs); the shared Edit menu
  carries Paste and Match Style, Find Next/Previous and Replace; the shared
  View menu carries Reload.  The dictionary's standard Edit list has the same
  editing entries, so known editors and document applications get them too.

*** Changed

- *The volume and brightness HUD now belongs to the bar.* It sits above the
  bottom edge, centred, instead of hanging from the top; it shows the reading's
  name and value above a thicker level bar, uses the bar's palette and accent,
  and keeps a top highlight and shadow so it reads as the same material.
- *The default look is the dark graphite glass of the late 2000s.* The
  built-in bar and the shipped example now wear =gloss-2007= instead of a
  hand-spelled near-dark palette.  A highlight runs along the top edge, a black
  hairline closes the bottom, and the menu bar is square while popovers keep
  the palette's rounded corners.
- *The default shell menu is a session menu.* Network, Bluetooth and
  Notifications are no longer repeated there; their bar modules, CLI options
  (=--network=, =--notifications=) and keybindings remain.  The menu's reload
  and quit entries and its separators now follow the launcher directly.
- *The architecture document* describes the supervisor, clean shutdown and the
  layer option; the shell-menu and module docstrings no longer promise panel
  entries that are not there.

*** Fixed

- *JetBrains Toolbox no longer shows a black tray icon on the dark bar.* Whelk
  read =IconName= only through GTK's desktop icon theme and ignored the
  =IconThemePath= the applet publishes beside its binary.  Tela's same-named
  =toolbox-tray-color= is a =currentColor= glyph, which renders black on a dark
  bar; the applet's own colour PNG is now preferred, with the theme and ARGB
  pixmap as fallbacks.
- *Restoring a clipboard entry no longer crashes the shell.* The GDK union
  content provider takes ownership of the providers it is given, but whelk
  also released them through the temporary array.  GDK then walked freed
  provider state while serving the Wayland clipboard request, producing the
  SIGBUS/SIGSEGV seen when restoring a copy.  The children are now released
  exactly once.
- *A Wi-Fi refresh no longer leaves rows pointing at freed access points.* The
  de-duplication table freed the =AccessPoint= values that had already been
  handed to the row widgets, so clicking a network or refreshing the list
  could dereference or double-free them.  The table now owns only its keys.
- *Restarting the clipboard listener cannot be undone by an old read.* A read
  queued against the previous =wl-paste= process is ignored after a restart or
  resume instead of stopping the replacement watcher.
- *A clipboard alert that outlives its bar module no longer touches freed
  state.* The module's state is reference-counted across the asynchronous
  dialog callback, and clearing is skipped once the module is gone.

** v0.11.1 (2026-11-13)

*** Fixed

- *Clipboard settings are read after the settings file, not before it.* The
  shell asked for `(clipboard-settings)` before `init-shell!` had loaded the
  configuration, so it saw the empty default and ignored the persistence,
  caps, retention and clear-on-lock the file configured.
- *Clear-on-lock can retry after a failed bus lookup.* A system-bus lookup that
  failed or was disabled in flight left the pending flag set, so enabling it
  again would never start a new watch.

** v0.11.0 (2026-11-13)

*** Added

- *Privacy controls with an off switch.* The clipboard bar module's right-click
  menu pauses and resumes capture, clears unpinned entries, confirms a full
  clear, restarts a dead listener and opens the picker.  The same controls are
  available as =--clipboard-pause=, =--clipboard-status=, =--clipboard-clear=,
  =--clipboard-clear-unpinned= and =--clipboard-restart=.
- *Retention and a lock policy.* =clipboard-settings= in Scheme sets
  persistence (off, the state file, or a path), pinned-only persistence, an
  expiry for unpinned entries, the entry count, per-entry and total byte
  budgets, and clear-on-lock.  Clear-on-lock follows logind's =LockedHint= and
  keeps pinned copies.
- *The picker recognises what it is showing.* Images get thumbnails; every row
  has its type, size and age; pinned entries form the first section; rows carry
  the store's stable content id so a copy arriving while the picker is open
  does not move the selection.  =Ctrl+Z= undoes a deletion.
- *Copied files are recorded.* =text/uri-list= is preferred over its plain
  text, listed as "1 file"/"N files", and restored as a URI list.
- *Rich content restores more than one representation.* HTML offers its plain
  rendering, and images that are not PNG also offer PNG, so ordinary
  applications asking for the fallback still paste something.
- *The global menu has more than Close.* File gains =New Window= from the
  desktop entry's =Exec=, and Window gains maximize/restore, toggle floating
  and move left/right/up/down wherever niri, sway or the X11 session can carry
  them out.  The menu is useful without =wtype=, because these verbs do not
  need a chord typed into the application.
- *End-to-end clipboard tests.* Stub =wl-paste= and =wl-copy= programs exercise
  the real helper and restore path: secret-hint refusal, image over HTML,
  plain rendering of HTML, binary framing, an oversized source, and the exact
  =wl-copy --type= invocation.

*** Changed

- The history is bounded by memory as well as count: 32 MiB per entry and
  128 MiB total by default, evicting the oldest unpinned copy.  The helper caps
  its own reads and times out a slow source.
- Persistence is debounced and written on a worker thread; shutdown flushes the
  last change.  The v1 history file still loads, and the new v2 file adds
  stable ids and copy times.
- Exact-MIME duplicates became content-id duplicates, so the same text under
  =text/plain= and =text/plain;charset=utf-8= is one entry.

*** Fixed

- *The helper can no longer put its own diagnostics into the record stream.*
  Debug and info lines go to stderr; before, a secret-hint or timeout message
  became part of the next framed record and the listener dropped it.
- A =wl-paste --watch= that dies now leaves the picker saying "listener
  stopped" instead of "no history", and can be restarted from the bar or CLI.

** v0.10.1 (2026-11-13)

*** Fixed

- *A clipboard record split inside its header waits for the rest.* The parser
  used to treat a short read before the header's newline as a malformed record
  and discard it, losing the copy.  Only an unterminated header longer than any
  the helper could write is dropped now.
- *A corrupt history file cannot take the shell with it.* The persistence file
  is validated as a normal GVariant before it is read, and a file that is not
  one is ignored; the next copy replaces it.
- *The history file is made private on every save.* A pre-existing file with
  wider permissions is chmodded back to 0600 instead of only new files getting
  the mode.
- *A pending clipboard read cannot touch a freed clipboard.* The read callback
  starts the next read while it still holds its reference, rather than after
  dropping the last one.

** v0.10.0 (2026-11-13)

- *An applet's menu is opened in whelk, not asked of the applet.* A right click
  on a tray icon reads its =com.canonical.dbusmenu= menu: =AboutToShow= first,
  then =GetLayout=, and choosing a row sends =Event(id, "clicked")=.  The tree is
  read one level shallower than a menubar's -- a context menu is the root's
  children -- with the same reader the global menu uses.  An item with no =Menu=
  path still gets =ContextMenu=, and one whose primary action is its menu opens
  it on a left click too.
- *A volume and brightness HUD.* When a reading changes, the shell shows a
  macOS-style card with the glyph, a bar and the number, then takes it away
  after a moment.  One surface for the whole shell, so two bars cannot draw two;
  the first reading a module takes is not a change and raises nothing.
- *The clipboard keeps images, rich text and what you decide to keep.* An entry
  is a MIME type and its bytes, not a line of text: a copied image returns as
  =image/png=, an HTML fragment as =text/html=, and plain text stays plain.  A
  password manager's =x-kde-passwordManagerHint= selection is refused before it
  is stored.  In the picker, =Ctrl+P= pins an entry (pinned entries do not fall
  off the fifty-copy cap) and =Ctrl+Delete= removes one.  Persistence is opt-in:
  =WHELK_CLIPBOARD_PERSIST=1= keeps the history in a 0600 file under
  =$XDG_STATE_HOME/whelk/=, a value with a slash names the file, and unset still
  means memory only.  The framing, MIME choice, secret hint, history rule and
  persistence are tested without a compositor.
- *Do not disturb and the clipboard are native modules.* =dnd-module= reads
  and toggles whelk's own notification state -- the tile is on the bar while
  DND is on, and hides itself while it is off unless =#:show-off? #t= -- and
  =clipboard-module= shows the shell's history depth and opens the picker on a
  click.  The default bar's =makoctl= and =clipman= custom modules are gone;
  neither program is needed, and the DND tile appears because the state is the
  shell's own.
- *The changelog is NEWS.org.* This file replaces =CHANGELOG.md=; the history
  below is the same history.
- *The volume and brightness readings are the glyph alone by default.* A bar
  that wants the number asks for it in its own =#:format=, e.g.
  ="{icon} {percent}%"= or ="{icon} {volume}%"=.  The numbers remain in the
  tooltips, and =backlight-module= finally reads =#:format= at all.

*** Added

- *DBusMenu menus are followed, not snapshotted.* The menu module now
  subscribes to ~LayoutUpdated~ and ~ItemsPropertiesUpdated~ on the object that
  published the menu, debounces the bursts, and reads the whole tree again, so
  a Firefox or Thunderbird menu that changes while it is open cannot send
  ~Event~ with an id from a layout that no longer exists: the open popover is
  closed first and every entry carries its id from the tree it was drawn from.
  A private-bus test covers both signals and the cancelled-read case.
- *Menu search, the Help menu's field.* ~--launcher-mode=menuitem~ (prefix
  ~:~) flattens the focused application's live menubar -- whatever producer
  made it -- into rows carrying the entry's path and chord, ranks them with the
  launcher's own fuzzy matcher, and activates the chosen one through the same
  code the bar's menu click uses. It reads the same tree the bar is showing, so
  a GTK, DBusMenu, scripted or dictionary menu is searchable identically.

*** Changed

- *The default bar's left half is the shell menu and the application's menus.*
  The focused window's title is no longer a module of the built-in bar; a bar
  that wants it puts ~(window-module ...)~ between ~start-module~ and
  ~menu-module~. The shipped settings example matches the default again.

** v0.9.0 (2026-11-13)

*** Added

- *A clipboard manager.* ~wl-paste --watch~ feeds a de-duplicated history
  (newest first, fifty entries, memory only), and ~whelk --clipboard~ or the
  launcher's ~;~ prefix lists it: choosing a row puts the copy back. The
  default bar's clipboard button opens that picker instead of ~clipman~.
- *About This System is a window now.* The shell menu's first item opens a
  card painted in the bar's palette: host name and system at the top, then the
  processor, memory, disk, kernel, session and uptime, with a button that copies
  the summary. It replaces the generic ~GtkAboutDialog~.
- *A shell menu that is configuration.* The popover behind the mark at the far
  left of the bar is now built from ~(whelk menu)~ units written in the settings
  file -- ~(menu-item "Sleep" "systemctl suspend")~, ~(menu-separator)~,
  ~(menu-submenu "Recent Items" "shell:recent-items")~ -- with
  ~default-shell-menu~ as the menu a file that writes none gets. The default is
  the Apple menu's shape in this desktop's words: About This System (the machine
  described in its own window), System
  Settings, Software, a Recent Items submenu filled from GTK's recent list when
  it opens, Force Quit, Sleep/Restart/Shut Down, Lock Screen and Log Out,
  followed by the shell's own panels. Actions spelled ~shell:name~ are the
  shell's (~about~, ~launcher~, ~force-quit~, ~network~, ~bluetooth~,
  ~notifications~, ~dnd~, ~reload~); anything else is a command line.
- *The left half in macOS' order.* The default bar is now the shell menu, the
  window in front's name in bold, and the application's File/Edit/View -- where
  the reference bar puts its mark, its window title and its system menu.
  ~menu-module~ keeps its application-name variant behind ~#:app-name?~ for a
  bar that would rather have two items than three.
- *DBusMenu, the other menu protocol.* ~com.canonical.dbusmenu~ is read as
  well as ~org.gtk.Menus~, so Qt and KDE applications' own menus appear in the
  bar: ~GetLayout~ for the tree, the item's ~shortcut~ for the chord, and
  ~Event(id, "clicked")~ when an entry is chosen. The window-scoped
  ~.../window/0/menus/menubar~ path is probed too.
- *A menu the configuration writes.* ~menu-module~'s ~#:menu-command~ runs a
  program that prints ~Menu<TAB>Item<TAB>Chord<TAB>Command~ lines, and those
  become the focused application's menus -- the escape hatch for an application
  no bus describes, with no rebuild.
- *rofi's script protocol in the launcher.* A menu generator that prints
  ~label\0icon\x1f…\0nonselectable\x1ftrue~ rows is read as bytes rather than as
  text, so its icons appear, its rules are not selectable, and choosing a row
  runs the generator again with ~ROFI_RETV=1~ and the label, the way rofi's own
  script mode does.
- *~ssh~ and ~quit~ launcher modes.* ~--launcher-mode=ssh~ (prefix ~%~) lists
  the hosts ~~/.ssh/config~ names and opens one in a terminal, which is rofi's
  ~ssh~ mode; ~--launcher-mode=quit~ (prefix ~!~) lists the open windows and
  closes the chosen one, which is what the shell menu's Force Quit opens.

*** Changed

- *mako's numbers.* A toast stays ten seconds when the application does not
  say (mako's ~default-timeout~ in the reference configuration), five toasts are
  visible at once (~max-visible~), and a critical one still never expires on
  its own.
- ~whelk --launcher-mode~ documents the full mode list: app, window, run, calc,
  file, web, menu, ssh, quit, clipboard.
- *The notification centre and its toasts.* The centre's header now carries
  the count (it was written to a label that was never built), each group wears
  its application's icon and a count pill, cards gained padding, hover and
  action-button styling, and the empty state is an icon with a sentence rather
  than one grey line. Toasts carry up to two action buttons, so a notification
  can be answered without opening the centre.

** v0.8.0 (2026-11-13)

*** Added

- *One application-name menu on the left.* ~menu-module~ now begins with the
  focused application's short name, and that name is a menu button: the
  launcher, the network and Bluetooth panels, the notification centre, a
  reload and quitting are behind it, and the application's own
  File/Edit/View follow. The default bar no longer puts the whelk mark and the
  focused window title beside it, so there is one menu instead of two;
  ~(start-module)~ is still available for a bar that wants the mark as well.
  The short name is the dictionary's name, else the desktop entry's name, else
  the last component of the application id (~com.jetbrains.toolbox~ becomes
  ~Toolbox~).
- *A Window menu for the applications the shell serves.* Full Screen and
  Close Window use the compositor's own actions, so a menu has the two window
  commands a menu bar is expected to have even when the application publishes
  no menubar. Desktop actions still come first in File.
- *Emacs multi-key chords.* A chord may be a sequence: ~C-x C-s~ is parsed,
  printed in either notation, and typed as ~C-x~ then ~C-s~, rather than being
  refused because it contains a space. Emacs itself is in the dictionary with
  sequences such as ~C-x C-s~, ~C-x C-f~, ~C-x b~ and ~C-x k~; the dictionary
  now covers ninety-five applications and two hundred and eighty ids.
- *A working, overflowing tray.* The tray reads the standard
  ~RegisteredStatusNotifierItems~ property, registers the bar as a
  StatusNotifierHost, and follows items registered after it starts, so a
  running JetBrains Toolbox appears. ~#:max-items~ (six by default) keeps the
  first icons on the bar and puts the rest behind a chevron.
- *Right-side bar overflow.* When the right row no longer fits the monitor,
  its trailing modules move behind a chevron in the row. The same widgets keep
  their timers, tooltips and clicks, so a clipped reading is not lost.

*** Changed

- *The sound icon is the familiar speaker.* The default volume glyph is
  ~\uf028~, and muting swaps it for ~\uf026~, instead of the unfamiliar
  broadcast mark.
- *Bluetooth and notification counts are hover text.* Their default formats
  are the glyph alone; the connected-device and waiting counts remain in the
  tooltips and are still available to an explicit ~#:format~.

*** Fixed

- *The tray was reading a property almost no watcher publishes.* It asked
  for ~RegisteredStatusItems~; the protocol's name is
  ~RegisteredStatusNotifierItems~, which is what Waybar and other modern
  watchers expose. It also registers as a host now, so an item that was already
  running is listed rather than waiting for a registration signal that has
  already happened.
- *A whitespace chord was rejected by the Scheme validator* before the C
  parser could read it as a sequence. A sequence is now a valid dictionary
  item, and an empty chord is still refused with the reason.
- **The application-name menu disappeared when the application had no
  menus.** The shell's own launcher/panel/reload/quit menu was gated on the
  application menus being non-empty, so a session with no shortcut tool (or no
  focused window) lost the whole left item. The name is now always present;
  the row only hides when ~#:app-name?~ is off and there are no menus either.
- *The tray chevron stayed behind after the watcher vanished.* Clearing the
  item list now reflows the chevron and the overflow popover too.
- *~add-menu-app~ logged with unescaped quotes.* The message's example
  ~(replace-menu-app "id" ...)~ ended the Scheme string early, so Guile warned
  ~possibly unbound variable \~~a'` and the diagnostic was garbled. The example
  now uses a quoted symbol and the file compiles without that warning.

*** Tests

- ~tests/test_chord.c~ covers sequence parsing, both display styles, both
  typing tools, and a sequence with a bare final chord.
- ~tests/test_menutree.c~ renders Emacs's ~C-x C-s~ from the dictionary and
  checks both the printed chord and the two typed commands; the Scheme suite
  accepts a multi-key item and still rejects one with no chord.

** v0.7.1 (2026-11-13)

*** Changed

- *The Wi-Fi reading hides the network's name by default.* The bar shows the
  icon and the hover text shows the signal, not the SSID; ~#:show-ssid? #t~
  names it again. An explicit ~#:format~ or ~#:tooltip~ still wins, because it
  was asked for.

*** Fixed

- *The menu reads the documented ~#:shortcuts?~ and ~#:app-name?~ keys.* It
  had looked for ~shortcuts~ and ~app-name~, so the question-mark spellings
  shown in the README were ignored. The older spellings still work.

** v0.7.0 (2026-11-13)

*** Added

- *The global menu reads both chord notations.* An item may be written as
  ~(label chord)~ with the chord in Emacs notation (~C-v~, ~M-F4~, ~C-S-p~,
  ~s-p~) or CUA notation (~Ctrl+V~, ~Alt+F4~), and the runtime translates it
  into the modifiers and keys ~wtype~ or ~xdotool~ type. The long
  ~(label chord modifiers key)~ form is still read. ~#:accelerator-style~
  chooses how the menu prints every chord: ~'cua~ by default, ~'emacs~ for
  ~C-v~ rather than ~Ctrl+V~.
- *The menu bar shows shortcuts wherever it can.* A menubar exported over
  D-Bus now has its ~accel~ attributes read and printed beside the labels, so
  an application that publishes its menus also shows the keys those menus
  answer to. The dictionary's entries keep printing the chord they type.
- *Forty-four more applications in the dictionary*, written in Emacs
  notation: browsers (qutebrowser, Falkon), terminals (foot), editors (Geany,
  mousepad, pluma, xed), file managers (PCManFM, Krusader, Double Commander),
  office suites (ONLYOFFICE, AbiWord, Gnumeric), mail (Geary), graphics
  (darktable, Scribus), video editors (Shotcut, Pitivi, OpenShot), media
  players (Strawberry, Parole, SMPlayer), PDF readers (Zathura, MuPDF), chat
  (Element), note-taking (Joplin, Typora), developer tools (Postman, DBeaver,
  Meld, Bitwarden), desktop utilities (Flameshot, Archive Manager, Ark), audio
  production (LMMS, MuseScore), CAD (FreeCAD, OpenSCAD), study (Anki, Calibre,
  Foliate, Zotero), and the system's own panels. Ninety-four applications
  answer to two hundred and seventy-seven ids, and more existing entries accept
  extra ids: Opera and Chrome variants, mate-terminal, xfce4-terminal,
  terminator, caja, kwrite, Ristretto, Clementine and Mullvad Browser.
- *A menu bar that can be used like a menu bar.* The focused application's
  name comes first, submenus wear a right chevron, and the keyboard walks the
  menus: Down and Up through the items, Home and End to the ends, Left and
  Right between top-level menus, Right into a submenu, Escape out.
  ~#:app-name?~ turns the name label off.
- ~tests/test_chord.c~ covers the parser, formatter and both typing tools; the
  menutree and dictionary suites cover Emacs-stored items, the GTK ~accel~
  attribute, both display styles, and duplicate chords after translation.

*** Changed

- The dictionary may store either notation; the four-field form remains for a
  chord the parser cannot spell.
- A submenu is a menu button with a right chevron rather than a second label,
  and its entries are reachable from the keyboard like the rest.

*** Fixed

- A bare ~C-~ -- a modifier prefix with no key behind it -- is refused rather
  than read as a key name.

** v0.6.0 (2026-11-12)

*** Added

- The menu dictionary answers to a settings file: ~add-menu-app~ appends an
  application the built-in table does not know, ~replace-menu-app~ puts an entry
  of your own where the one answering to an id stood, and the runtime reads the
  result at startup and after every reload. A bad entry -- an item with no
  chord, a menu with nothing in it, two items typing one chord -- is refused and

** v0.3.2 (2026-11-12)

*** Fixed

- *Session detection no longer depends on an exported variable.* ~NIRI_SOCKET~
  and ~SWAYSOCK~ are inherited only by the processes a compositor spawned, and

** v0.3.0 (2026-11-12)

*** Added

- *A session layer, so the shell knows where it runs.* ~src/util/session.c~
  detects niri, sway, an X11 desktop or a Wayland session with no

  is in front, and how to close it. ~NIRI_SOCKET~ and ~SWAYSOCK~ identify their

** v0.2.0 (2026-11-12)

*** Added

- *The shell's own menu.* ~start-module~ puts one glyph at the head of the
  bar, and behind it the launcher, the network panel, the notification centre,
  a settings reload and quitting. The glyph is the configuration's.
- *A global menu.* ~menu-module~ shows the focused application's menubar,
  read from D-Bus (~org.gtk.Menus~, the interface GTK publishes a menubar on)

  six levels deep, with caches, repositories and package trees skipped
  (~.cache~, ~.git~, ~node_modules~, ~.venv~, …). Matches are ranked in C — a
  name match above a path match, a shallower path above a deeper one, files
  above folders of the same name — and the walk is reused for thirty seconds
  so typing does not cost one walk per key.

  now follow the compositor's size.

  module, so windows slid under it: the reserved zone is the painted width.
- The launcher's file mode re-ranked an already ranked list by basename, which
  dropped every result that matched further up its path.
