** v0.42.0 (2026-11-18)

*** Added

- *A task list: the bar can be a taskbar.*  =(tasks-module)= puts every open
  window on the bar as a button, grouped by workspace, with the session's own
  window list (niri's `windows`, sway's tree, `hyprctl clients`, `wmctrl -lp`).
  A click focuses a window and the middle button closes it, the two gestures an
  XP taskbar has; the focused window is marked, and an answer this module does
  not understand is an empty list rather than a broken bar.  The XP preset's
  centre is that module now, so the preset is a taskbar instead of a title.
- *Fold priorities.*  A reading can say how much it wants to stay:
  =#:keep? #t= is the loudest, =#:priority= a number to tune (a clock at 100
  outranks a load average at 10), and a reading that says nothing keeps the
  positional default, so an unconfigured bar folds exactly as it did.  The fold
  is now recomputed whenever the surface is given a new width -- a scale change,
  a rotation, a font that grew -- instead of once after the first allocation,
  and the row is re-answered from the whole set, so a reading that was folded at
  the old size comes back at the new one.
- *The shelf is remembered.*  Opening the overflow chevron saves
  =bar-overflow-expanded?= as a GUI preference, and the next load (or reload)
  opens it again: a reader who opened the shelf does not lose it to a save that
  had nothing to do with it.
- *Battery time and two packs.*  =(battery-module)= reports ={time}= -- seconds
  until the pack is empty, or until it is full while charging -- computed from
  =energy_now=/=power_now=, or from =charge_now=/=current_now= scaled by the
  pack's voltage.  =#:device "all"= sums every pack in the machine: the
  percentages are weighted by capacity, the rates are added up, and any pack
  that is charging makes the machine charging.
- *An About whelk window.*  =whelk --about=, and *About whelk* in the shell
  menu, open the program's own report: version, running session, GTK, the
  settings file in use, and where the documentation, the source and the two
  package channels are.  *Copy* copies it, *Escape* closes it.  The machine's
  own report (*About This System*) is unchanged beside it.
- *Presets can be overridden.*  =use-preset!= takes =#:bars=, =#:widgets=,
  =#:shell-menu= and =#:clipboard= to replace any part of the bundle, and a
  preset's own bar constructor takes every =bar= keyword
  (=(xp-bar #:height 40 #:accent "#80ff80")=), so changing one colour no longer
  means forking the preset.  =#f= means "the preset's own", which is how ='()=
  says "no desktop widgets".
- *A preset can be switched without editing a file.*  =whelk --preset xp=
  switches the running shell and remembers the choice, =whelk --preset current=
  goes back to the shipped bar, =whelk --preset forget= hands the shell back to
  =settings.scm=, and =WHELK_PRESET=xp whelk= does it for one run.  The choice
  is saved as the =preset= GUI preference, so it survives a restart, shares the
  override file with the settings window and disappears with its Reset.  The
  order is: =WHELK_PRESET= for the run, then the remembered choice, then the
  settings file -- a switcher that only worked on files without a
  =(use-preset! ...)= line would not be a switcher.
- *A native MPRIS module.*  =(mpris-module)= shows what is playing and controls
  it by talking to the player's own =org.mpris.MediaPlayer2.Player= interface:
  no =playerctl=, no polling of one process per player.  ={title}=, ={artist}=,
  ={album}=, ={player}=, ={state}=, ={position}=, ={length}=, ={progress}= and
  ={art}= are the reading; =#:player= names one player and defaults to the
  player that last reported it was playing, so the bar follows the music; a
  left click is play/pause, the middle button is next, the right button is
  previous, and =#:art? #t= shows a local cover.  The default bar's now-playing
  tile uses it instead of the two-second =playerctl= command.

*** Changed

- A bar's rows are rebuilt when the surface is resized, which is also when the
  fold answers again; the fold used to be a single pass after the first map.

*** Fixed

- *The wallpaper covers the whole screen again.*  A layer surface anchored on
  all four edges is clipped to the output but never enlarged to it, and a GTK
  window has to ask for a size; the background surface now asks for the
  monitor's geometry, which is the same rule the bar already followed.  It was
  drawn in one corner of the screen before this.
- *The wallpapers are picked by whelk, not by `heks-toon`.*  The bar's picture
  tile is `(wallpaper-module)`: a click opens whelk's own card of thumbnails
  and a right click the full picker, so choosing a picture no longer leaves the
  shell for another program.  The shelf loses the duplicate wallpaper tile and
  the `heks-toon palettes` tile beside it.

*** Verified

- =cargo fmt --all --check=, =cargo clippy --workspace --all-targets -- -D
  warnings= and =cargo test --workspace= pass (556 tests), and so do the Guile
  suites.
- The taskbar was run in a live niri session: the row listed the workspace
  number and its five windows as truncated buttons, and the XP preset's centre
  is that module.
- =whelk --about= opened the new window in that same session, with the version,
  the session and the settings path.
- Presets were switched in a live shell: =WHELK_PRESET=xp= and a saved
  =(preset . xp)= both registered the XP bar over a settings file that asked for
  something else, and the GUI overrides were layered on top of it.
- The wallpaper was checked on an empty niri workspace: it filled the whole
  1880x1253 output, with the desktop widgets over it.
- The MPRIS parsing, player choice and time formatting are pinned by 12 tests;
  the tile itself has *not* been seen against a real player yet, and its
  controls have not been clicked -- it is the one part of this release that
  ships tested but not exercised.
- The Guix and Nix builds, and the smoke install, pass.

** v0.41.4 (2026-11-17)

*** Fixed

- *The night light actually warms the screen on niri.*  The gamma table was
  written into a memory descriptor and the descriptor was handed to the
  compositor without rewinding it, so it arrived with the file offset at the end
  of the table it had just written.  wlroots maps the descriptor from zero and
  never noticed; niri reads it from the current offset, got nothing, and
  answered `failed` -- so on niri the filter took the output, was refused, and
  the screen stayed cool however the schedule was set.  The table is now
  rewritten to offset zero before `set_gamma`, and a test reads it back through
  the same descriptor to pin that down.
- *One refused output no longer turns the whole filter off.*  A `failed` event
  used to clear the colour the backend wanted, so a single output that another
  gamma client held (or that had no table) stopped the write for every other
  output as well.  It now drops only that output's control, with its
  thirty-second backoff, and leaves the rest warm.
- *A write that reached no output is reported as a failure*, so the engine keeps
  the previous colour and tries again on the next tick instead of believing the
  screen was changed.  Together with the backoff, a compositor that refuses
  gamma gets one request per half minute, not one per fade step.

*** Verified

- Reproduced and then fixed against niri 26.04 on an AMD output: a control
  answers `gamma size 4096`, and writing the table **without** rewinding the
  descriptor gets `failed`, while the same table rewound is accepted.  whelk's
  own binary went from `gamma FAILED for output 44` to no failure at all.
- =cargo fmt --all --check=, =cargo clippy --workspace --all-targets -- -D
  warnings= and =cargo test --workspace= pass (525 tests, the new
  `the_gamma_table_reads_back_from_its_start` among them), and so do the Guile
  suites.
- The Guix and Nix builds, and the smoke install, pass.

** v0.41.3 (2026-11-17)

*** Added

- *A wallpaper menu, opened where the user asks for it.*  A right click on an
  empty desktop, or a click on the bar's new =(wallpaper-module)=, opens a card
  of thumbnails: the current picture outlined, the count in the header, and a
  click on a picture applies it through the same =wallpaper-selected= preference
  the picker writes.  The card opens at the pointer (flipped when it would hang
  off the output) or under the reading (above it for a bar at the bottom).
  *Esc*, the close button and any click back on the desktop dismiss it, and a
  collection of more than twelve pictures keeps the rest behind *Browse all…*,
  which opens the picker.
- *A background that answers clicks.*  whelk now keeps one transparent
  =background=-layer surface per monitor, so the clicks nothing else wants land
  on the shell.  It reserves no space, cannot take a click from a window, and
  exists even when the engine is not drawing a background.
- The menu is its own layer surface cut to the card -- so a compositor that
  blurs a surface blurs the menu instead of the output, the same rule the
  launcher follows -- and its thumbnails arrive one per idle callback, through
  the picker's own queue.

*** Changed

- *The bar never prints the wallpaper's details.*  The "wallpaper: enabled ·
  5400s · crossfade · cover · 3 paths" reading is gone from the centre of the
  bar; the pictures are one click away in the menu instead.
- The example settings, the built-in default bar and the heks-linux render use
  =(wallpaper-module)= where they used a =custom-module= that ran
  =heks-toon walls=: nothing about the wallpapers leaves whelk now.

*** Verified

- The menu was opened in a live niri session against the operator's own three
  wallpapers: the card landed on the requested point (626, 246 with the measure
  of the card, 380x173), the thumbnails decoded, and the "not drawing a
  background" line appeared with the engine off.
- =cargo fmt --all --check=, =cargo clippy --workspace --all-targets -- -D
  warnings= and =cargo test --workspace= pass, including the new menu tests

- The Guix and Nix builds, and the smoke install, pass.

** v0.41.2 (2026-11-17)

*** Fixed

- *The Nix package reaches the GPU instead of falling back to cairo.*  A
  nix-built whelk links =libEGL= from libglvnd, whose compiled-in vendor
  directory is inside the store; on a host that is not NixOS the drivers live
  elsewhere, so EGL found no vendor at all.  Every surface then reported
  =Gsk-WARNING: Failed to realize renderer 'GskGLRenderer' ... Failed to create
  EGL display= and GTK painted with cairo -- which is why a frosted, blurred bar
  felt slow there.  The wrapper now names the nix Mesa EGL vendor json, its DRI
  directory and its GLX vendor with =--set-default=, so the driver that matches
  the card (radeonsi, iris, llvmpipe ...) runs through the kernel's render node
  and no library from the host is loaded into the process.  An environment that
  already names its vendors wins, so a [[https://github.com/nix-community/nixGL][nixGL]]
  setup and the proprietary NVIDIA path still decide, and =EGL_PLATFORM= stays
  GTK's business.  =docs/installation.org= records the failure and the
  override.

*** Verified

- On an AMD Phoenix host (openSUSE, so =/run/opengl-driver= does not exist),
  =GSK_RENDERER=gl= on the packaged binary logged six =Failed to create EGL
  display= warnings before the change and none after, and the running shell
  holds =/dev/dri/renderD128= open: the GL renderer is on the GPU.
- The same binary with =__EGL_VENDOR_LIBRARY_FILENAMES= already set kept that
  value and failed as expected, which is what =--set-default= is for.
- =nix-build -E 'with import <nixpkgs> {}; callPackage ./default.nix {}'=
  builds the package, its tests and its wrapper; =cargo fmt --all --check=,
  =cargo clippy --workspace --all-targets -- -D warnings= and =cargo test
  --workspace= pass, and so do the Guile suites.
- The Guix build already had working EGL on the same host and needed no
  wrapper; its package only follows the version.
- The Guix and Nix builds, and the smoke install, pass.

** v0.41.1 (2026-11-17)

*** Changed

- *The launcher is the card, not the output.*  Its layer surface used to be
  anchored to all four edges, so a compositor that blurs a surface -- niri's
  =layer-rule { match namespace="^whelk-rust-launcher$"; background-effect {
  blur true } }=, the arrangement =docs/materials.org= recommends -- blurred the
  whole screen on every keystroke and every caret blink, which is what made the
  launcher feel slow there.  The surface is now the card plus the room its own
  shadow needs (792x752 for a 720x680 card on a 1880x1253 output, instead of the
  whole output), positioned with layer-shell margins so the card keeps its
  place, and it follows a card resize.  Closing is unchanged: =Esc=, the close
  button, and handing the keyboard to another window all dismiss it.
- *One settings file, one parse.*  Every group of settings -- bars, widgets, the
  shell menu, the menu sources, the wallpaper, the night light, the clipboard,
  the finish -- asked Guile to read and evaluate the same file, so one shell
  load parsed the configuration eight times and every reload did it again.  The
  handle now remembers the evaluation, stamped with the file's modification time
  and size, and re-reads on a reload, a rewrite, or a GUI preference write.  A
  load parses the file once.
- *A save next door no longer rebuilds the shell.*  The configuration directory
  is watched, and any event in it used to schedule a reload: a rotated log or an
  editor's lock file re-evaluated the settings and rebuilt every bar.  Only the
  settings file and =.scm= files in that directory are news now.

*** Fixed

- *The bar starts with the shell's own menu, not with a name.*  The left row
  opened with a =whelk= label carrying the settings path in its tooltip; it is
  gone, and the path moved to the bar's own hover text, so the start mark is the
  first thing on the bar.
- *A module switch written as =#f= now turns the switch off.*  The Scheme
  constructor dropped every =#f= option value before the bridge saw it, so an
  option whose default is on could never be turned off: =#:app-name? #f= on the
  menu module still drew the application-name button, and =#:show-ssid? #f= or
  =#:show-capacity-when-charging? #f= fell back to their defaults.  The option
  readers already match on type, so a =#f= is still "no value" for a string, a
  number or a symbol, and it is now the written "off" of a boolean.  The
  built-in bar and =docs/menus.org= have always described the application name
  as off; the ship now does what they say.
- *Bar popovers stop fighting for the grab.*  A layer surface can have one
  grabbing popup at a time, so opening the start menu on top of an open
  application menu (or the =+N= shelf, or a tray menu) was refused by GDK --
  =Tried to map a grabbing popup with a non-top most parent= -- and the click
  did nothing at all.  The bar now keeps one registry of its popovers and each
  item closes the others before it opens its own; the menu bar's hover-switch
  does the same.
- *Clicking a menu no longer replaces it with the shell's own.*  When the
  compositor reports no focused window -- the desktop, the overview, or one of
  whelk's own surfaces holding the keyboard while a menu is open -- the global
  menu rebuilt its row as the shell's fallback =File/Edit/View/Window=, which
  destroyed the popover that had just been clicked.  An empty answer now leaves
  the application's menus alone; only the first answer, before any application
  has been shown, builds the shell menu.
- *A chosen row runs after its popover is down.*  A chord typed by the shortcut
  tool, or a compositor verb such as Close Window, acts on whichever window
  holds the keyboard; running it in the same turn as the click sent it to the
  bar instead of the application the menu describes.

*** Verified

- =cargo fmt --all --check=, =cargo clippy --workspace --all-targets -- -D
  warnings= and =cargo test --workspace= pass, and so do the Guile suites
  (=test_defaults.scm= among them: the example settings and the built-in bar
  still describe the same bar).
- The built shell was run beside a live niri session: the bar draws the mark,
  then =File= and =Window=, with no name label and no application-name button;
  menus open, replace each other and stay open; =Tried to map a grabbing popup=
  no longer appears.
- The launcher was measured the same way: its surface reports 792x752 for a
  720x680 card on a 1880x1253 output (0.60 MP of compositor blur instead of the
  output's 2.36 MP), the card keeps its place and its shadow, and the launcher
  still dismisses when another window takes the keyboard.
- A load of the example configuration logs one =Reading settings from=, and a
  touched =.scm= beside it one more; a =.txt= in the same directory logs none.
- The Guix and Nix builds, and the smoke install, pass.

** v0.41.0 (2026-11-17)

*** Added

- *Frosted glass, configurable once and painted everywhere.*  A new
  =(frosted-glass ...)= setting, registered with the rest of the shell as
  =#:frost=, gives every surface a warm translucent finish: a tint and its
  opacity, two soft gradients that catch the light like a pane, a grain that
  keeps a blurred backdrop from banding, a hairline along the top edge and a
  shadow under floating panes.  The bar, the launcher, the desktop widget cards,
  the notification centre and its toasts, the network panel and the on-screen
  display all generate their skin in one place, so one setting reaches them
  together instead of six near-copies drifting apart.
- *A materials page.*  =docs/materials.org= explains which half of a frosted
  look a Wayland client can paint and which half only the compositor can, lists
  the layer namespace of every whelk surface, and ships working recipes for niri
  (=layer-rule= with =background-effect=), Hyprland (=hl.layer_rule= and the
  older =layerrule=) and SwayFX (=layer_effects=), plus what to do on a
  compositor that has no backdrop blur at all.

*** Changed

- An empty =#:tint= keeps each surface's configured colour, so the finish can be
  added to an existing bar or theme without repainting its palette.  A settings
  file that never mentions =#:frost= is unchanged, and the finish is clamped to
  sane ranges so a typo cannot make a pane unreadable.

*** Fixed

- *Saving a GUI preference no longer drops the finish.*  The settings window
  re-registers the shell record from the bar it just edited; =#:frost= is now
  carried across with the wallpaper and the idle and night-light policies, so
  changing the bar's height does not flatten every pane back to its opaque
  skin.

*** Verified

- =cargo fmt --all --check=, =cargo clippy --workspace --all-targets -- -D
  warnings= and the workspace tests pass, including the new =tests/frost.rs=.
- =tests/test_frost.scm= covers the constructor, the alist the bridge reads and
  the GUI-overlay round trip; =test_wallpaper.scm= and =test_defaults.scm= still
  pass.
- The Guix and Nix builds, and the smoke install, pass.


*** Fixed

- *The shell no longer aborts when a bar's timer has already fired.*  Cancelling
  a module's work removed a main-loop source that could already be gone, and
  GLib treats the id of a missing source as a programmer error: the gtk-rs
  wrapper panics, and a panic inside a GIO or GTK callback cannot unwind, so
  the process died and the supervisor restarted it in a loop.  Every source
  removal now goes through one helper that ignores an id that no longer names a
  source.
- *The launcher lists the installed applications again.*  The XDG variables
  name data directories and desktop entries live in their =applications=
  subdirectory; whelk scanned the data directory itself, so no entry was ever
  found.  The global menu's desktop-entry lookup, which resolves an
  application's name and icon, reads the same directories and is fixed by the
  same change.
- *The bar spans its output.*  The Rust port had dropped the C surface's size
  request and marked the window non-resizable, so an anchored bar laid out at
  the width of its modules.  The window now asks for the monitor's width (or
  height, for a vertical bar) minus its margins and accepts the compositor's
  configure events.

*** Verified

- =cargo fmt --all --check= and =cargo clippy --workspace --all-targets -- -D
  warnings= pass.
- =cargo test --workspace --locked= passes, including the new regressions:
  removing a fired one-shot source is a no-op, removing a pending one cancels
  it, and desktop entries are looked up in =applications=.

** v0.40.0 (2026-11-17)

*** Security

- *Scheme modules are loaded only from paths the user or installer chose.*
  A packaged whelk no longer searches the working directory or the build-time
  =CARGO_MANIFEST_DIR=, either of which could load a module from an
  attacker-writable directory.  Development runs name the tree explicitly with
  =WHELK_SCHEME_DIR=; staged installs resolve beside the binary and packaged
  installs use =/usr/share/guile/site/3.0=.
- *logind property signals use the standard properties interface.*  The locker,
  idle manager and clipboard now subscribe to =PropertiesChanged= on
  =org.freedesktop.DBus.Properties=, so a signal on the session interface
  cannot impersonate a logind property change.
- *Suspend waits for the lock screen to report readiness.*  Before
  =PrepareForSleep(true)= the shell takes a logind sleep-delay inhibitor and
  holds it until the lock process has acquired =ext-session-lock-v1= or built
  its layer-shell fallback.  A lock that cannot start releases the delay
  instead of suspending behind a screen that is not up.
- *The lock screen fails closed.*  If the compositor implements session-lock
  and refuses it, or if neither session-lock nor layer-shell is available, the
  lock exits with failure rather than showing an ordinary or transparent
  window that input can escape.  The remaining surfaces are opaque, and one
  strong reference now owns the lock state while weak callbacks observe it.
- *Notification bodies keep only emphasis markup.*  Pango =span= tags are
  removed and their text escaped, so a notification from any session client
  cannot spoof shell text or request extreme font metrics.  Unbalanced tags
  remain plain text.
- *Bluetooth addresses are validated before reaching a command line.*  The
  network panel accepts exactly six colon-separated hexadecimal octets and
  ignores malformed or forged BlueZ rows.
- *Chord keys no longer slice through UTF-8.*  A pasted multi-byte key is kept
  whole instead of panicking at a fixed byte offset.
- *Menu expansion has a total node budget.*  Depth alone did not stop a wide
  =org.gtk.Menus= graph that reused sections; the walk now stops after 4096
  rows.
- *Clipboard persistence resists symlinks and scope changes.*  Saves use a
  randomly named =O_EXCL= temporary file in a directory that must be private
  and owned by the user, and the watcher rechecks =CLIPBOARD_STATE= and the
  offered types around every read.

*** Changed

- *The development gate matches the packaging repository.*  =maak test= now
  cleans the target directory, uses the shell's own =cargo-clippy= through a
  private =CARGO_HOME=, and runs the suite before clippy.  =maak clippy= is the
  lint-only task; =manifest.scm= adds =rust-src= and =gdb=, and =maak run= and
  =maak debug-run= set =WHELK_SCHEME_DIR= for the development tree.
- *The Guix manifest loads the Rust package correctly.*  =manifest.scm= now
  imports =(gnu packages rust)= and selects the =out=, =cargo= and =tools=
  outputs, so the shell has the compiler, Cargo, rustfmt and clippy.

** v0.39.3 (2026-11-17)

*** Changed

- *The Guile bridge uses static C strings.*  Module and procedure names are
  `c"..."` literals passed straight to the checked `&CStr` boundary, so loading
  the configuration no longer allocates or panics on an impossible NUL.  The
  Rust-version primitive reads a compile-time NUL-terminated byte string.
- *The network panel's pages are concrete types.*  Wi-Fi controls are required
  fields of `WifiPage` rather than nine `Option`s followed by five `expect`s;
  Bluetooth has its own page type, and both share a common builder that keeps
  the original widget order.
- *Menu paths descend without an unreachable branch.*  A recursive walk returns
  the final submenu or `None`; a malformed path stops instead of panicking, and
  the parser's mutable borrows stay local.
- *Widget drag setup and the lock service name are panic-free.*  A card whose
  child is not the expected box simply skips drag setup, and PAM receives a
  static `c"whelk-lock"` service name.

*** Documentation

- *The vision now describes the project it became.*  =VISION.md= records the
  Rust-only implementation, the six menu producers and eleven launcher modes,
  the floating widgets as they actually place and drag, and adds the engineering
  principles: pure decisions, audited unsafe boundaries and errors instead of
  panics for malformed input.  Its milestones now run through 0.39.3, and the
  remaining reserved work is stated without pretending it already exists.
- *The hacking guides are rewritten around Rust.*  =docs/development.org= now
  has the current code map, the =maak= and Cargo commands, the three test layers
  including the Guile harness, a change recipe, the unsafe policy, a module
  recipe, debugging commands and a review checklist.
  =docs/contributing.org= states the same expectations for contributors:
  test-first behaviour changes, ownership, evidence and release notes.
- *Architecture, modules, releasing and the index follow.*  Architecture names
  the three kinds of code and their rules; the module page documents the Rust
  factory path instead of the retired C one; releasing lists all seven checked
  places and the Guix/Nix channel handoff; the README and documentation index
  link =VISION.md= and describe the current Rust tree.

*** Verified

- =cargo fmt --all --check= and =cargo clippy --workspace --all-targets -- -D
  warnings= pass.
- =cargo test --workspace --locked --offline= passes: 502 tests, including the
  Guile harness.
- The pinned Guix build and the Nix package build the same source.

** v0.39.2 (2026-11-17)

*** Changed

- *The POSIX boundary is one audited module.*  =posix.rs= now owns signal
  installation, process signalling and =getpid=; the UI and the supervisor no
  longer repeat their own =sigaction= setup.
- *The supervisor's restart policy is a pure function.*  An =Outcome= is
  classified once and =decide= returns an =Exit= or =Restart= decision, which is
  tested without spawning a child.
- *The pure modules use composition instead of manual state.*  Fuzzy scoring is
  a =try_fold= over the query, =best= uses a maximum key, playlist resolution
  uses =Option= combinators, and a level update assigns one new value instead of
  repeating field writes.
- *The PAM conversation uses slices.*  Raw response arrays are no longer walked
  with =offset=, and the configuration loader propagates a missing Guile handle
  instead of panicking on an invariant.

*** Verified

- =cargo fmt --all --check= and =cargo clippy --workspace --all-targets -- -D
  warnings= pass.
- =cargo test --workspace --locked --offline= passes: 502 tests, including the
  8 new safety/policy cases, plus the Guile harness.
- The pinned Guix build and the Nix package build the same source.

** v0.39.1 (2026-11-17)

*** Changed

- *The Rust dependencies are vendored.*  =rust/vendor= carries every crate in
