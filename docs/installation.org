#+title: Installation
#+subtitle: whelk documentation
#+options: toc:nil num:nil

What has to exist on the machine before whelk can start, what the binary looks for at run time, and the four ways to install it.

* What you need
:PROPERTIES:
:CUSTOM_ID: requirements
:END:

- GTK 4 (>= 4.10 for =gdk_monitor_get_connector=; developed against 4.24)
- =gtk4-layer-shell= (>= 1.2, for =ext-session-lock-v1= and the fallback)
- GNU Guile 3.0, with its development headers
- Optional: the separate =hasp= program for lock actions and logind-triggered
  locking (see [[#lock-screen]]).  Whelk builds and starts without it.
- Rust 1.92 or newer, Cargo, =pkg-config=
- =wayland-scanner=, which generates the river-status client binding at build
  time
- Optional, found at run time: =niri=, =swaymsg=, =hyprctl= or =riverctl=
  (compositor IPC), =xprop= (X11 window focus), =wtype= or =xdotool= (typing a
  menu shortcut), =cava= (the visualizer card's spectrum), =nmcli=,
  =bluetoothctl=, =wlsunset=

Nothing on that second list is required to start: whelk asks for what is there
and hides what is not.

* The optional lock screen
:PROPERTIES:
:CUSTOM_ID: lock-screen
:END:

=ldd $(command -v whelk)= lists GTK 4, =gtk4-layer-shell=, the Wayland client,
GIO and Guile.  It does not list =libpam=, and whelk does not load it either:
the lock screen is a separate program, [[https://github.com/jjba23/hasp][hasp]].

Whelk starts that program when it is needed:

- =hasp --watch= once at startup, to follow logind;
- =hasp --lock= for a lock request from the menu, =--lock= or the idle timer;
- =hasp --check= for =whelk --check-lock=.

The program is found through =HASP_BIN=, a sibling binary or =$PATH=.  A
machine without hasp still runs the shell; a lock action reports the missing
program and how to install it.  A package should recommend hasp rather than
link it.  PAM, the lock surfaces, the retry policy and hasp's own theme live in
that project, not here; [[file:lock-screen.org][The lock screen]] is the runtime contract.

* Guix
:PROPERTIES:
:CUSTOM_ID: guix
:END:

whelk lives in the [[https://github.com/jjba23/guix-jointhefreeworld][jointhefreeworld
channel]]:

#+begin_src sh
  # once, in ~/.config/guix/channels.scm:
  #   (channel
  #    (name 'jointhefreeworld)
  #    (url "https://github.com/jjba23/guix-jointhefreeworld")
  #    (branch "trunk"))
  guix pull
  guix install whelk
#+end_src

For hacking on it, the repository pins its own toolchain, so the build is the
same one CI runs:

#+begin_src sh
  guix shell -m manifest.scm          # the pinned development environment
  guix shell -D -f guix.scm           # just the dependencies
  guix time-machine --channels=channels.scm -- build -f guix.scm
#+end_src

=maak run= and =maak test= wrap the shell and test commands in
=guix time-machine --channels=channels.scm=, so they are reproducible even when
the channels in =~/.config/guix= have moved on.

* Nix
:PROPERTIES:
:CUSTOM_ID: nix
:END:

=default.nix= is a plain =callPackage= expression:

#+begin_src sh
  nix-build -E 'with import <nixpkgs> {}; callPackage ./default.nix {}'
  ./result/bin/whelk
#+end_src

The binary is wrapped for the machine it runs on rather than the machine it was
built on.  A nix-built GTK4 app links =libEGL= from libglvnd, whose compiled-in
vendor directory is inside the store; on a host that is not NixOS the GPU
drivers live elsewhere, so EGL finds no vendor, GTK's GL renderer reports
=Failed to create EGL display=, and every surface falls back to cairo.  The
wrapper names the nix Mesa vendor (=__EGL_VENDOR_LIBRARY_FILENAMES=), its DRI
directory (=LIBGL_DRIVERS_PATH=) and its GLX vendor
(=__GLX_VENDOR_LIBRARY_NAME=) with =--set-default=s: an existing value wins, so
a host GL setup such as
[[https://github.com/nix-community/nixGL][nixGL]] or the proprietary NVIDIA
path still decides.  =EGL_PLATFORM= is deliberately left alone -- GTK asks for
the platform its GDK backend is on.

* From source
:PROPERTIES:
:CUSTOM_ID: source
:END:

Whelk is a Cargo workspace at the repository root:

#+begin_src sh
  cargo build -p whelk-rs --release
  cargo test --workspace --locked       # the Rust and Guile suites
  ./target/release/whelk
#+end_src

Whelk finds its Scheme modules in =WHELK_SCHEME_DIR= (when set), in
=PREFIX/share/guile/site/3.0= beside the installed binary, or in
=/usr/share/guile/site/3.0=.  A build that is run without installing must set
=WHELK_SCHEME_DIR= to the checkout's =scheme/= directory; the working directory
is deliberately not searched.

Install it with the project's staging task:

#+begin_src sh
  cargo xtask install --prefix=/usr --destdir="$DESTDIR"
#+end_src

`xtask` stages =whelk=, the shared =scheme/whelk= modules, the desktop entry,
the hicolor icon tree and the README.  The binary also finds the modules beside
its own prefix, so =/usr/local= and staged package roots work without an
environment variable.

* Distribution packages
:PROPERTIES:
:CUSTOM_ID: packages
:END:

=packaging/= carries recipes for the four families; each builds the same
installed layout described in [[file:packaging.org][Packaging and distribution]].

#+begin_src sh
  maak deb-build     # Debian/Ubuntu .deb, from packaging/debian
  maak arch-build    # Arch package, from packaging/arch/PKGBUILD
  maak rpm-build     # RPM for openSUSE and Fedora, from packaging/opensuse
  xbps-src pkg whelk # Void package, from packaging/void/template
#+end_src

* Starting, and stopping
:PROPERTIES:
:CUSTOM_ID: starting
:END:

Start whelk inside the session, from a keybinding, or from your compositor's
autostart.  If your environment forces the X11 backend (=GDK_BACKEND=x11=), a
layer surface cannot be created and whelk falls back to a plain window -- start
it inside the Wayland session instead:

#+begin_src sh
  GDK_BACKEND=wayland whelk
#+end_src

Quit with =Ctrl+C= in its terminal, =whelk --quit=, or
=gapplication quit org.jointhefreeworld.whelk=.
