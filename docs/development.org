=maak=, the test layers, CI, and the house rules.

* The maak tasks
:PROPERTIES:
:CUSTOM_ID: maak
:END:

=maak= runs the project's common operations; =maak= with no argument lists the
tasks it finds.

#+begin_src sh
  maak run          # run whelk inside the pinned Guix environment
  maak test         # fmt, clippy and the Cargo suite in that environment
  maak cargo-build  # release build in the current shell
  maak debug-run    # debug build, then gdb
  maak deb-build    # .deb, built from packaging/debian
  maak arch-build   # Arch package, built from packaging/arch/PKGBUILD
  maak rpm-build    # RPM for openSUSE and Fedora, from packaging/opensuse
#+end_src

The Guix tasks read =channels.scm= and =manifest.scm=, so they run in the pinned
toolchain.

* The test suite
:PROPERTIES:
:CUSTOM_ID: testing
:END:

#+begin_src sh
  cargo fmt --all --check
  cargo clippy --workspace --all-targets -- -D warnings
  cargo test --workspace --locked
#+end_src

The suite has three layers:

#+name: test-layers
#+caption: The suite climbs from pure decisions to the widget-backed data model; each layer exists because the one below it cannot answer that question.
#+begin_src mermaid
flowchart TD
    P["pure Rust<br/>JSON, matchers, calculator,<br/>wallpaper, schedules, state"] --> W["widget-backed models<br/>bar modules, menus, notifications,<br/>lock screen rebuilds, preferences"]
    W --> S["a real shell model<br/>one Guile handle, bar plans,<br/>surfaces and reload boundaries"]
    G["the Guile suite<br/>themes, the built-in bar, overrides,<br/>the widget contract"] --> S
#+end_src

- =rust/tests/policy.rs=, =settings.rs=, =collection.rs=, =rotation.rs= --
  wallpaper formats, fit and easing, clamps, HOME/XDG rules and rotation.
- =rust/tests/bar.rs=, =barmonitors.rs=, =barmodules.rs= -- typed bar
  defaults, monitor rules and every module's reading.
- =rust/tests/launcher*.rs=, =clipboard.rs=, =notifications*.rs=,
  =networkpanel.rs= -- the launcher databases, calculator, clipboard history,
  notification store/service and network parsers.
- =rust/tests/lockauth.rs=, =locker.rs=, =lockpolicy.rs=, =logind.rs=,
  =idle*.rs= -- authentication policy, lock rebuilds and the idle manager.
- =rust/tests/preferences.rs=, =widgets.rs=, =widgetstate.rs=,
  =desktopwidgets.rs= -- the settings model, Golden Gate card data and the
  placement file.
- =rust/tests/config.rs=, =guile.rs=, =scheme.rs= -- the real Scheme modules,
  a repeated load through one Guile handle, and the retained Guile test scripts
  (=tests/test_*.scm=), run by Cargo when =guile= is installed.

The tests that need a private session bus say so in their own file: the
notification round trip and the AT-SPI menu test run under
=dbus-run-session=.  A test that cannot get its bus skips rather than failing.

The old C-only golden-image, Xvfb night-light and headless-Sway locker scripts
were removed with the C shell.  The Rust equivalents are the policy and model
tests above; the GTK surfaces still need a real compositor for a visual check.

* CI
:PROPERTIES:
:CUSTOM_ID: ci
:END:

=.github/workflows/ci.yml= calls Byggsteg with =tasks: maak-test=, so a green CI
run and a green =maak test= are the same commands in the same environment as
=guix shell -m manifest.scm=.

The former ASan/UBSan workflow is gone with the C implementation.  Rust's
memory safety is checked by the compiler, and =cargo test= is the gate for the
Rust and Guile suites.

* House rules

:CUSTOM_ID: rules
:END:

The repository's own guides are short and worth reading before a patch:

- The conventions, in [[file:architecture.org][Architecture]]: keep every =SCM= behind
  =rust/src/guile.rs=, keep =unsafe= at the C-library boundary, and make a new
  module a =*bar.rs= file plus a =barfactory.rs= row.
- [[file:../AI_POLICY.md][AI_POLICY.md]] -- how AI-assisted contributions are handled, including the
