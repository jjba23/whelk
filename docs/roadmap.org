* Where the next pieces go
:PROPERTIES:
:CUSTOM_ID: next
:END:

The direction behind this table is [[file:../VISION.md][Vision]]: a single
programmable process, a functional core, an audited FFI edge and a shell that
degrades instead of breaking.  The open work below is deliberately smaller than
that statement.


- *Editable notes*: Notes renders the value a settings file or a note file
  gives it.  Editing the prose from the card would write through a preference
  override, the same reversible path the settings window already uses; a
  reminder's done state already takes that path.
- *Configured surfaces*: =bar->alist= in =state.scm= is the pattern; a record for
  the launcher or the panels would be the same trick applied once more.
- *One monitor for the panels*: bars follow =#:monitor=; the panels, the toasts
  and the launcher still open on the first output (see
  [[file:known-limits.org][Known limits]]).
- *A tray menu that follows its tree*: a tray menu is read when it opens
  ([[file:tray.org][The tray]]); the global menu is the one that follows =LayoutUpdated=.  Making
  the tray watch as well is one more subscription, not a new model.
- *More module kinds*: a pomodoro timer, a weather reading or an MPRIS queue is
  three steps each ([[file:modules.org][Modules]]).
