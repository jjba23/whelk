#+title: Modules
#+subtitle: whelk documentation
#+options: toc:nil num:nil

Twenty-two module kinds, one shape: the options they share, the options each one adds, and a worked example.

All constructors are the same shape -- a kind plus keyword options -- and all
accept the shared options:

| Option                           | Meaning                                                       |
|----------------------------------+---------------------------------------------------------------|
| =#:icon=                           | a glyph, drawn from the bar's =#:icon-font=                    |
| =#:format=                         | how the reading is rendered; ={icon}= is the glyph             |
| =#:interval=                       | seconds between refreshes (0 = render once)                    |
| =#:tooltip=                        | hover text; ={text}= is the current reading                    |
| =#:on-click=, =#:on-click-right=, =#:on-click-middle= | shell commands on the mouse buttons     |
| =#:on-scroll-up=, =#:on-scroll-down= | shell commands on the wheel                                  |
| =#:css-class=                      | an extra CSS class on the module's own widget                  |

Unknown options are ignored rather than rejected: a settings file can be ahead
of the binary, which is what makes upgrading whelk safe.  A boolean switch takes
=#t= or =#f= as written: =#f= is how a switch that defaults to on is turned off
(the built-in bar's =(menu-module #:app-name? #f)=), and for a value that is not
a boolean -- a string, a number or a symbol -- =#f= means "no value", so the
module's own default applies.  Nor do options have to
be edited in the file: the settings window's *Modules* page writes each module's
options as GUI overrides, and its *Show in the bar* switch hides a module while
leaving the configuration untouched.

| =audio-module=         | wpctl (PipeWire), falling back to pactl          | =#:muted-format=, =#:muted-icon=, =#:format= (default ="{icon}"=), ={volume}= |

A worked example of the whole set is in =settings/settings.scm=, which also has a
commented-out workspace switcher for the centre of the bar.

#+begin_src scheme
  ;; A module is a value, so a list of them is a list like any other.
  (define (status-item kind . options)
    "A reading, with the two clicks everything on this bar has."
    (apply kind #:on-click "whelk --launcher"
           #:on-click-right "whelk --notifications" options))

  (bar #:name 'main #:theme 'tinted-2024 #:height 30
       #:left   (list (menu-module))
       #:center (list (window-module #:format "{title}"))
       #:right  (map (lambda (kind) (status-item kind))
                     (list cpu-module memory-module clock-module)))
#+end_src

* What a module is

#+name: module-shape
#+caption: A module is a value with a widget, a timer and a destroy function; Rust owns the typed value and the factory table, Scheme owns the constructor.
#+begin_src mermaid
flowchart LR
    K["(clock-module #:format ...)<br/>a Scheme record"] --> B["rust/src/guile.rs<br/>a typed module alist"]
    B --> F["rust/src/barfactory.rs<br/>the factory table"]
    F --> W["a root widget<br/>on a bar row"]
    F --> T["a refresh timer<br/>#:interval seconds, 0 = once"]
    T --> U["update: read, then render"]
    W --> X["destroy, on a reload"]
    U --> X
    X --> G["ModuleGuard<br/>a late command writes nowhere"]
#+end_src

* Adding a module

A module is a small Rust change plus its settings surface:

1. add =rust/src/<kind>bar.rs= with the typed reading, its options and the
   widget builder.  Keep the parsing and policy functions testable without GTK.
2. register the kind in =rust/src/barfactory.rs= and extend the options reader
   in =rust/src/bar.rs= when the module takes a new keyword.
3. add the constructor or default in =scheme/whelk/modules.scm= only if the DSL
   should expose a named constructor; otherwise the generic record is enough.
4. add a focused test in =rust/tests/= and a row to this page with a working
   settings snippet.

The factory boundary is also the failure boundary: an unknown kind is logged and
left out, and a constructor that cannot build does not stop the rest of the bar.
[[file:architecture.org][Architecture]] has the boundary rules, [[file:development.org][Development]] has the house
style, and [[file:lifecycle.org][Lifecycles]] has the refresh path in detail.
