Debian, Arch, RPM and xbps recipes, and the layout a packaged whelk installs.

Packaging lives under =packaging/=: =debian/= (debhelper), =arch/= (=PKGBUILD=),
=opensuse/= (spec file, rpmlint filters and the OBS =_service=) and =void/
(=xbps-src= template, for a distribution without systemd -- see
[[file:portability.org][Portability]]).
=packaging/pam/whelk-lock= is an optional, reviewed PAM stack for the locker;
install it as =/etc/pam.d/whelk-lock= only after checking it against the
distribution's PAM policy.

* What a packaged whelk installs

#+name: installed-layout
#+caption: The install prefix decides the Scheme load path at configure time, which is why a package built with --prefix=/usr never needs the source tree.
#+begin_src mermaid
flowchart LR
    P["--prefix=/usr"] --> B["/usr/bin/whelk"]
    P --> D["/usr/share/applications/<br/>org.jointhefreeworld.whelk.desktop"]
    P --> I["/usr/share/icons/hicolor<br/>the whelk mark"]
    P --> S["/usr/share/guile/site/3.0/whelk/<br/>core, loader, state, modules,<br/>defaults, themes, presets, orbit"]
    S -.->|"baked in at configure time"| B
    R["resources/css/whelk.css<br/>compiled in as a GResource"] --> B
#+end_src

A packaged whelk installs the binary, the desktop entry and the icon tree, and
the Scheme modules under =/usr/share/guile/site/3.0/whelk/=.  The binary looks
for the modules beside its own prefix as well as in the system Guile path, so a
package or staging root works without being started from the source tree.  The
bar's structural and thematic CSS is generated by the Rust surfaces; there is no
separate stylesheet for a package to lose.

* The four recipes

| Family              | Built with                | Result                       |
|---------------------+---------------------------+------------------------------|
| Debian/Ubuntu       | =maak deb-build=            | a =.deb=, from =packaging/debian= |
| Arch                | =maak arch-build=           | a package, from =packaging/arch/PKGBUILD= |
| openSUSE and Fedora | =maak rpm-build=            | an RPM, from =packaging/opensuse= |
| Void                | =xbps-src pkg whelk=        | an xbps package, from =packaging/void/template= |

The Void template is copied to =void-packages/srcpkgs/whelk/= and its checksum
is filled with =xgensum -i whelk=; it builds the workspace and installs with
=cargo xtask install= like the others, and declares no session-manager
dependency.  Its =version= is one of the places the release script checks, so
it moves with every release even though the checksum is only filled when the
template is copied into void-packages.

Each one builds the same installed layout, and each one carries the version the
release script keeps in agreement (see [[file:releasing.org][Releasing]]).

* What a packager has to keep

- The Scheme modules must land in the package's Guile site directory, or in a
  directory pointed at by =WHELK_SCHEME_DIR=.  =cargo xtask install= stages
  them under the same prefix as the binary.
- =libpam= is a run-time dependency, not a link-time one: do not add it to the
  package's =NEEDED= set to "be safe".  [[file:installation.org][Installation]] has the candidate order
  and the reason.
- The locker's PAM service is optional and belongs to the distribution's
  policy, not to this project.  Review =packaging/pam/whelk-lock= before
  installing it.
