#+title: Desktop widgets
#+subtitle: whelk documentation
#+options: toc:nil num:nil

Floating Golden Gate cards, described by the same file as the bar, placed in pixels and moved by their grip.

Desktop widgets are floating cards on the background layer, described by the
same file that describes the bar.  The standard collection is one value:

#+begin_src scheme
  (configure-shell!
   #:bars (list (default-bar))
   #:widgets (golden-gate-widgets))
#+end_src

The widget gallery this shell can
power from GNU/Linux: **Clock**, **Calendar**, **Weather**, **Batteries**,
**Notes**, **Reminders**, **World Clock**, **Stocks**, **Now Playing**,
**Visualizer**, **Media**, **Photos**, **Files**, **News**, **System** and
**Custom**.  Each card drags by
its grip, snaps to an 8px grid and stays inside its monitor.  The position is
remembered per monitor, so the same widget can sit somewhere different on the
laptop panel and the desk screen; a monitor that is unplugged falls back to the
last place the widget was seen, clamped into the screen that is left.

The same records can be written out one at a time, placed anywhere on any
output:

#+begin_src scheme
  (configure-shell!
   #:widgets
   (list
    (desktop-widget 'clock #:x 40 #:y 64)
    (desktop-widget 'weather
                    #:x 40 #:y 320
                    #:width 340
                    #:height 220
                    #:monitor "DP-1"
                    #:options '((location . "Amsterdam")
                                (latitude . 52.3676)
                                (longitude . 4.9041)
                                (units . metric)))
    (desktop-widget 'notes
                    #:x 400 #:y 64
                    #:options '((title . "Today")
                                (text . "Ship the release.")))))
#+end_src

| Key             | Meaning                                                              |
|-----------------+----------------------------------------------------------------------|
| =#:x=, =#:y=       | pixels from the edges of =#:anchor= (top-left when nothing is pinned) |
| =#:width=, =#:height= | the card's size; wins over =#:size= when given                    |
| =#:size=          | ='small=, ='medium= (default) or ='large=: the kind's size in one of the three size families |
| =#:anchor=        | ='top-left= (default), ='top=, ='top-right=, ='left=, ='center=, ='right=, ='bottom-left=, ='bottom=, ='bottom-right= |
| =#:monitor=       | ="default"= or a connector such as ="DP-1"=                            |
| =#:options=       | the widget's own alist; an unknown key is ignored                     |

Every kind accepts =#:title=, =#:css=, =#:tooltip=, =interval= (seconds between
reads; zero paints once, and it wins over the kind's own cadence), the mouse
actions =on-click=, =on-click-middle=, =on-click-right=, =on-scroll-up= and
=on-scroll-down= (each a command line), and a material of its own:
=foreground=, =background=, =accent=, =opacity=, =blur=, =radius=, =shine=,
=reflection= and =flare=.  A card with no material is the first bar's skin, so
the desktop looks like one shell; a card that names one changes only what it
names.  Two more switches are not materials: =transparent?= removes the card's
background, border and shadow entirely, for a visualizer or a media card that
should float on the wallpaper, and =header? #f= leaves only the grip in the
header so the content gets the whole card.  The kind-specific options are:

| Kind          | Options                                                            |
|---------------+--------------------------------------------------------------------|
| =clock=         | =style= (=analog= or =digital=), =timezone=, =format= (a =strftime= string), =date-format=, =show-seconds?= |
| =calendar=      | the current month, with today marked; =show-week-numbers?= adds ISO week numbers; =‹= and =›= change it, the month title returns to today |
| =weather=       | =latitude=, =longitude=, =location=, =units= (=metric= or =imperial=), =forecast-days= |
| =battery=       | =device=, =warning=, =critical=                                      |
| =notes=         | =text=, or =file= to read the note from disk and re-read it when its mtime changes |
| =reminders=     | =items=, a list; prefix an item with =x= to mark it done; a row toggles when clicked; the card counts what is left |
| =world-clock=   | =cities=, as ="Name=Zone"= entries separated by commas; =day-night?= marks night with a moon |
| =stocks=        | =symbols=, a list of Yahoo Finance tickers; each row draws the day's closes as a sparkline |
| =now-playing=   | the session's MPRIS player: title, artist, position and previous/play/next buttons; =player= names one when several are running |
| =visualizer=    | a live spectrum from [[https://github.com/karlstav/cava][cava]]: =bars= (32), =framerate= (30), =mirror?=, =peaks?=; needs =cava= on =PATH= |
| =media=         | transport and seek for the session's MPRIS player: artwork, title, a seek slider, previous/play/next; =player= chooses one |
| =photos=        | =path= (or =paths=), a folder or a comma-separated list; scroll or click the picture |
| =files=         | =file=, a recent-documents XBEL (the desktop's own by default); =limit= |
| =news=          | =feeds=, one or more RSS/Atom URLs (or =url=); =limit=                |
| =system=        | CPU, memory, load average and uptime from the kernel                  |
| =custom=        | =exec=, =interval=, =empty=; anything a command can print              |

Weather asks [[https://open-meteo.com][Open-Meteo]] for the current conditions, today's high and low and, with
=#:forecast-days=, that many days of highs and lows (give a forecast card a
taller =#:height= or =#:size 'large= so the days have room);
Stocks asks Yahoo Finance for delayed quotes and the day's closes;
News reads any RSS or Atom feed it is given.  None needs an API key, and
both keep their request off the main loop: the request is made by =curl= in a
child process, not by GIO, because a shell started by a compositor commonly has
no GVfs daemon and no HTTP backend behind it -- which is why these two cards
used to sit on "unavailable" while =curl= fetched the same URL in a second.
whelk's packages carry =curl= for that reason -- Nix puts its store path on the
wrapped binary's =PATH=, and the Guix package wraps the binary the same way, so
a compositor-spawned shell finds it without a login shell's environment.  The
request also names itself: Yahoo answers 429 to a request with no =User-Agent=
and 200 to the same URL with one.

A failed request never paints over a reading the card already has: the Weather
card keeps its conditions, a Stocks card keeps its quotes, and the reason moves
into the hover title -- *curl is not installed* with *install curl, or put it on
PATH* under it, or *Weather unavailable* for a network that did not answer.  A
card that has never loaded has nothing to keep, so it says the same words on the
card itself, and the shell prints one line to its log for a missing =curl=
rather than retrying a program that is not there every tick.

Ageing is the other half.  Every networked card carries the same =Health=:
=Ready= with the time of the last good read, =Stale= with the reading's
timestamp and the error that stopped the refresh, or =Failed= with the error and
when it last tried.  Once the reading is older than twice the card's refresh
interval -- an hour for Weather, ten minutes for Stocks -- one quiet line
appears under it, *42 min ago*, and is rewritten every thirty seconds so it does
not disagree with the clock between fetches.  A single failed refresh is silent:
a card that missed one tick is not worth a sentence, and the hover title has the
error for anyone who asks.

A card sits on the layer-shell =bottom= layer, takes no keyboard and reserves no
screen space, so it is visible on the desktop and under the windows rather than
over them.  Saving the settings file is compared with the set already on
screen: the same cards on the same outputs keep their surfaces, their timers,
their MPRIS subscription and the photo on display, so saving an unrelated bar
colour does not restart them.  A card set that really changed is rebuilt with
the bars.

* The visualizer and the media card

The =visualizer= card runs a private =cava= process and draws its raw ASCII
output as rounded bars, so the shell gets a real spectrum analyser without
linking an audio stack.  The bars follow the bar's accent colour, can mirror
around the centre with =#:mirror? #t=, and keep a thin falling cap over each
bar with =#:peaks? #f= to turn that off.  =#:bars= (8 to 64, default 32) and
=#:framerate= (10 to 60, default 30) are passed to cava when the card starts;
a card that is closed stops its cava and removes its private configuration.  A
miss shows the reason on the card instead of leaving an empty box.  The usual
way to make it a bare spectrum on the wallpaper is:

#+begin_src scheme
  (desktop-widget 'visualizer
                  #:x 80 #:y 420 #:width 520 #:height 220
                  #:options '((transparent? . #t)
                              (header? . #f)
                              (bars . 48)
                              (mirror? . #f)))
#+end_src

=transparent?= drops the card's own plate but keeps its content inset, and
=header? #f= keeps only the grip, so the bars are what is left.  Without either
switch the visualizer is an ordinary card and wears the same material as the
rest of the desktop.

The =media= card is the larger transport: local cover art, the track and its
artist, a seek slider that moves the player with =SetPosition= (or a relative
=Seek= when the player publishes no track id), elapsed and total time, and
previous/play/next.  It is the same MPRIS engine the bar's =mpris= and
=media-controls= modules use, so a click on the card and a click in the bar
reach the same player.  It is drawn as a card by default and takes the same
=transparent?= and =header?= switches.

* Families, anchors and a card's own material

Three things make a card a card rather than a fixed picture of one:

#+begin_src scheme
  (list
   ;; The big weather card, pinned 24px in from the bottom-right corner.
   (desktop-widget 'weather #:size 'large #:anchor 'bottom-right #:x 24 #:y 24)
   ;; A small clock that reads the time every ten seconds instead of one.
   (desktop-widget 'clock #:size 'small #:x 24 #:y 24
                   #:options '((interval . 10)
                               (opacity . 0.72)
                               (background . "rgba(20, 22, 28, 0.55)")
                               (accent . "#8fd16a"))))
#+end_src

- **Families.**  =#:size 'small= is three quarters of the kind's standard size
  and ='large= is half again as much, both rounded to the 8-pixel grid a drag
  snaps to and never smaller than 100 pixels; ='medium= is the standard size,
  untouched, so nothing anyone already placed moves.  =#:width= and =#:height=
  still win when they are written, because pixels are the configuration's word.
- **Anchors.**  =#:x= and =#:y= are distances from the anchor's own edges, so
  =#:anchor 'bottom-right #:x 24= is 24 pixels in from the right on any screen.
  A card keeps its corner when an output is a different size, which is what a
  card in a corner is for; a dragged position is saved as the same offset, so a
  drag on one screen is not undone by unplugging another.
- **Material.**  A card is skinned from the first bar's palette; naming one
  material key changes that one thing (a quieter background over a photograph,
  a warmer accent, a firmer radius) and leaves the rest of the bar's skin.

* Clicking, dragging and the grid

A widget is a window you can move, not a printout.  The small grip at the
top-right of every card is its drag handle: hold it with the primary button and
the card follows the pointer, snaps to an eight-pixel grid and stops at the
monitor's edges.  The grip is deliberately not the whole card, so the card's own
buttons and its calendar and reminder rows keep their clicks.  The position is
written to =$XDG_STATE_HOME/whelk/widgets-<settings-stem>.ini= (normally
=~/.local/state/whelk/widgets-settings.ini=) and restored on the next reload or
start; deleting that file returns every card to the position in the settings
file.  Dragging is a Wayland layer-shell move: the position is the surface's
margin from the monitor's top-left corner, not an X11 window coordinate.

Every card's primary, middle and right click and its two scroll directions are
commands from the settings file, so a Notes card can open the note in an editor,
a Weather card can refresh a script and a right click can show a menu.  What
needs no configuration is built in: the calendar's =‹= and =›= buttons change
the month and its month title returns to today; a Reminders row toggles between
done and not done and that state is saved in the same state file, with a line
above the rows that says how many are done and an empty state that says what to
configure; the player's previous, play/pause and next buttons drive the
session's MPRIS player and its progress bar follows the track; a photo card
pages through its folder on a scroll and opens the picture on a click; a Files
row opens the document it names and a News headline opens the article; the
clock, weather, stock, photo, file, news and system cards keep their own refresh
timers.  Notes remains read-only: its text is what the settings file or the
note file says.  It is drawn as prose rather than as a dump of a file -- words
wrap at word boundaries inside the card's =#:width= (a long line never widens
the surface past it), paragraphs keep one blank line between them, tabs are
expanded and trailing spaces go -- and a card with no =#:text= and no =#:file=
says so quietly instead of showing the note placeholder.

The standard set is a starting layout across a 1080p desktop -- the left column,
the middle, and a right column for the player, photos, files, news and the
system -- aligned to the same eight-pixel grid a dragged card snaps to.  It is
not privileged: use =map=, a helper procedure, or a list of your own to place
exactly the cards you want.  =custom= is the escape hatch for widgets whose data
comes from another program.

* The desktop menu

Right-clicking the wallpaper opens the desktop's own menu.  It is a card of the
shell's own making, not a list of commands the settings file has to assemble,
and every row is one of whelk's real operations:

| Section    | Rows                                                                 |
|------------+----------------------------------------------------------------------|
| Open       | Applications, Run a Command, Search Files, Calculator, Clipboard History, Notification Centre, Settings |
| Wallpaper  | Next, Previous, Shuffle Now, Choose from Collection, Open Picker       |
| Switches   | Night Light, Do Not Disturb, Keep Awake, Desktop Widgets             |
| Session    | Lock Screen, Sleep, Restart, Shut Down, Log Out, Session Menu         |
| Shell      | Reload Configuration, About This System, Quit whelk                  |

The menu reads its state when it opens, so the Night Light, Do Not Disturb,
Keep Awake and Desktop Widgets rows say what is true now, and the wallpaper
section names the picture on screen.  *Choose from Collection* opens the same
thumbnail card the wallpaper picker uses, at the menu's own place; *Next*,
*Previous* and *Shuffle Now* step the configured collection without opening a
picker, and *Open Picker* is the full chooser.  *Desktop Widgets* hides or
shows every card without rebuilding them, so the timers and the photo on
display survive.  *Reload Configuration* is the same reload a settings save
triggers; *Quit whelk* ends the process through GApplication, so a compositor
that supervises the shell can start it again.

The menu is a layer-shell surface cut to its card, on the top layer with an
exclusive keyboard while it is open: Escape closes it, a primary click on the
desktop closes it, and a row closes it before running its command.  It is
scrollable and never taller than the output it opened on.  The wallpaper
collection remains the fallback for a session with no desktop menu, so the
right click is never a dead click.

* The widget data
:PROPERTIES:
:CUSTOM_ID: widgets-rust
:END:

The Rust desktop-widget surfaces read and draw the same descriptions.
=rust/src/widgets.rs= is the data behind them: the sixteen kinds and their
standard sizes, the position/size/monitor defaults and clamps, the mouse
vocabulary and per-kind refresh cadence, the reminders model whose done flags
are runtime state, world-clock city parsing, the Open-Meteo/Yahoo/RSS-Atom
answer decoding, the calendar's Monday-first month grid and ISO week numbers, a
note's file-or-text rule, the photo folder walk, the recent-documents XBEL
reader, the system's =/proc= readers, the stock sparkline arithmetic, and the
drag/placement arithmetic (snap to the 8 px grid, clamp into the monitor, a
saved position winning over the settings file).  =rust/src/widgetstate.rs= is the
=widgets-<settings-stem>.ini= file the shell writes and reads, so a drag is
remembered across restarts; =Guile::load_widgets= reads
=shell-widgets->alists= into the same typed configs.  The =scheme= bar
module is Rust as well: =rust/src/schemebar.rs= calls =#:update= through
=rust/src/guile/widget.rs=, which registers the =whelk-widget-*= primitives in
=(whelk core)= and swaps the returned widget into the bar each refresh.

The cards are drawn by =rust/src/desktopwidgets.rs=: one bottom-layer surface per
configured widget, anchored at its saved or configured place, skinned from the
first bar's palette, moved by its grip (snapped to the grid and clamped into
the monitor), with a timer per kind, a second tick on Weather, Stocks and News
that only re-reads their age, and one asynchronous request at a time for each of
them.  The card CSS is installed once for the display instead of once per card;
a clock with no seconds and no analog face wakes four times rarer than one that
shows them; a note is re-read only when its file's mtime moved; a calendar or a
label that would draw the same words again is left alone.  A card that goes
away drops its timer, its skin and its surface, and an answer that arrives late
paints nothing.  The manager is rebuilt with the bars when the configuration,
the material or the outputs changed, and otherwise keeps the cards it has; the
same =widgets-<stem>.ini= means a drag survives a restart and is honoured when
the settings describe the same card.

The right-click menu has one pure half and one GTK half:
=rust/src/desktopmenu.rs= builds =sections()= -- the rows, their labels, their
state and the =DesktopCommand= each one carries -- from a =DesktopMenuState=,
so every row is tested without a display; =rust/src/desktop.rs= opens it at the
pointer, and =rust/src/ui.rs= performs the command with whelk's existing
launcher, notification, idle, power, lock, settings and wallpaper machinery.
