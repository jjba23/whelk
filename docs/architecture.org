* The boundaries are the design

- *Scheme never becomes a pointer in application code.*  =guile/sys.rs= owns
  the reviewed libguile declarations; =guile.rs= turns SCM values into owned
  Rust strings, numbers and lists.  No widget holds a =SCM= value.
- *A module is a value, not a subclass.*  A module kind is a row in
  =barfactory.rs=; its reading and widget live in the matching =*bar.rs= file.
  A module reports through the shared =barmodule.rs= host, so its timer,
  cancellation, deadline and mouse options are the same as every other kind.
- *A bar is configuration, a surface is not a bar.*  =ui.rs= turns a typed
  =BarSettings= into one layer-shell surface per selected output.  Launchers,
  panels, notifications and the locker use the same surface vocabulary without
  pretending to be a bar.
- *CSS is structure plus skin.*  =resources/css/whelk.css= is no longer a
  compiled resource; the Rust surfaces generate their structural and thematic
  CSS in =style.rs= and the per-surface modules, scoped to each window id.

* Three kinds of code, three rules

The tree is easier to change when a function declares which kind it is.

| Kind              | Examples                                                        | Rule |
|-------------------+-----------------------------------------------------------------+------|
| Pure decision     | =supervisor::decide=, =idlepolicy=, fuzzy scoring, playlist choice | no I/O; input and output are owned values; test every branch without a display |
| Fallible edge     | =ConfigLoader=, Guile evaluation, PAM answers, file parsers     | return =Result= or =Option= with a specific error; no production =expect= for user input |
| Unsafe boundary   | =posix.rs=, =guile/sys.rs=, =nightlight/=, and =hasp= (separate project) | =// SAFETY:= on every block, no pointer or =SCM= escapes, one C ABI per module |

A pure decision is the preferred shape for anything the shell will later do:
=Outcome= and =Decision= in =supervisor.rs= are a complete restart policy, and
the loop that sleeps and spawns only performs the answer.  A fallible edge keeps
the failure where the context exists: the config loader can name the settings
path, and the locker can say whether PAM, the helper or strict mode refused.  An
unsafe boundary is allowed to be unsafe inside, but its callers see a safe
function and its comments state what must remain true.

The 0.39 pass applied those rules in both directions: it moved repeated POSIX
calls into =posix.rs=, and it removed panics from page construction and menu
paths by making the data model express the invariant.  A new abstraction is
worth adding when it moves a decision into the first row of this table, not when
it merely hides a callback.

* How a bar becomes pixels

#+name: bar-pipeline
#+caption: A bar crosses four layers, and each one can be tested without the next.  A reload throws the last three away and builds them again.
#+begin_src mermaid
flowchart LR
    A["(bar #:name 'main ...)<br/>a Scheme record"] --> B["an alist<br/>state.scm: bar->alist"]
    B --> C["BarSettings<br/>plain Rust structs"]
    C --> D["bar window<br/>ui.rs"]
    D --> E["layer surface<br/>edge, anchors, margin,<br/>exclusive zone, monitor"]
    D --> F["module rows<br/>left, centre, right, overflow"]
    F --> G["BarModule<br/>a root widget + a timer"]
    D --> H["a generated CSS provider<br/>scoped to this bar's window"]
    H --> I["the bar on screen"]
    E --> I
    G --> I
#+end_src

The deep copy is what makes a reload safe: the Rust structs do not point into
the Scheme heap, so destroying every bar and building new ones from a fresh
evaluation has nothing to reconcile.  A module's own token covers the other
direction -- a command that finishes after its module was freed writes nowhere
(see [[file:lifecycle.org][Lifecycles]]).

* Where a change belongs

| You are adding                        | It goes in                                              |
|---------------------------------------+---------------------------------------------------------|
| a reading on the bar                  | =rust/src/<kind>bar.rs= and a row in =barfactory.rs=     |
| an option every module understands    | =barmodule.rs= and the reader in =bar.rs=                 |
| a widget keyword                      | =guile.rs= (read), =bibelot= (carry), =ui.rs= (present) |
| a bar keyword                         | =guile.rs= (read), =bar.rs= (carry), =ui.rs= (use) |
| a new kind of surface                 | =ui.rs= or its own module, over the shared surface helpers |
| a palette                             | =scheme/whelk/themes.scm=                               |
| a menu producer                       | =menubar.rs=, =menuprobe.rs= and =globalmenu.rs=          |
| a settings-window control             | =preferences.rs= and the page it belongs to             |
| a configuration entry point           | =scheme/whelk/core.scm=, and it must still be a value    |
| a policy decision                     | a pure module beside the surface, with a transition type and tests |
| a C-library call                      | the matching audited boundary (=posix.rs=, =guile/sys.rs=, =nightlight/=) |
