This directory holds whelk's manual.  The [[file:../README.org][README]] is the front door: what the
shell is, what it looks like and how to install it in five commands.  Everything
that needs more than a paragraph lives here, one document per subject, so a
question has one place to be answered.

* Three reading paths

** I want to use it

[[file:getting-started.org][Getting started]] -> [[file:configuration.org][Configuration]] -> [[file:modules.org][Modules]] -> the usage document
for whatever is on the bar.  Read [[file:known-limits.org][known limits]] before adopting it: the
ceilings are stated, not discovered.

** I want to hack on it

[[file:architecture.org][Architecture]] -> [[file:lifecycle.org][Lifecycles]] -> [[file:development.org][Development]] -> [[file:contributing.org][Contributing]].
The house rules are the short part of that path, and they are the ones a patch
is judged by.

** Something is wrong

[[file:installation.org][Installation]] for what the binary needs, [[file:sessions.org][Sessions]] for a compositor
that was not recognised, [[file:lock-screen.org][The lock screen]] for
"Authentication is unavailable", [[file:idle.org][Idle]] for a screen that did or did not
lock, and =whelk --idle-status= for the shell's own account of its decision.

* Conventions in these pages

- File names are literal; =code= is literal inside a sentence; *emphasis* marks
  a control or a menu label.
- Diagrams are mermaid, so they render on GitHub and in any editor that draws
  them; the prose beside each one is the contract, not the picture.
- Nothing here is a wish: a statement about behaviour is the behaviour the
  binary has, and [[file:known-limits.org][known limits]] is where the gaps live.
